# 小程序

## 微信小程序

小程序本质就是一个SPA单页面应用，所有的页面渲染和事件处理都在一个页面内进行，它的架构模式，是数据驱动模式，它的UI和数据是分离的，页面的更新都要数据驱动。技术和前端开发差不多，采用js、wxml、wxss。功能可分为webView、appService两部分，在两个进程中进行，通过系统层的JSBridge进行通信。
1. webView，用来展示UI，
2. appService，用来处理逻辑和数据，包括数据请求、数据存储、事件处理等。


## 小程序的主要目录和文件

1. project.config.json：小程序的配置文件，包括appid、appname、version，开启https校验等信息
2. App.js，设置一些全局的基础数据
3. App.json，底部tab，标题栏和路由设置
4. App.wxss,公共样式，引入iconfont等
5. pages，具体页面
6. index.json，配置当前页面标题和引入组件
7. index.wxml,页面结构
8. index.wxss，页面样式
9. index.js，页面的逻辑，请求和数据处理

## wxml和html的异同

1. 相同点：都是用来描述页面结构的语言
2. 都有标签和属性构成
3. 多了wx:if这样的属性和{{}}表达式等
4. 组件封装不同，wxml对组件进行了重新封装
5. 小程序运行在JS Core内，没有DOM和Window对象

## 封装微信小程序的数据请求

1. 在根目录下创建utils目录及api.js文件和apiConfig.js文件
2. 在apiConfig.js文件中配置请求的url和请求方法、请求头、带上token和异常处理
3. 在api.js文件中引入apiConfig.js文件，根据页面数据请求url，设置对应方法并导出
4. 在具体的页面中引入接口并在统一的文件中导出
5. 在app.js中创建封装请求数据的方法
6. 在子页面中调用封装的请求数据

## 小程序传递数据

1. 页面跳转或重定向时，使用url带参数传递数据
2. 使用组件模块template传递参数
3. 使用缓存传递参数
4. 给wxml元素添加data-xxx传递，通过e.currentTarget.dataset.xxx获取
5. 设置id标识传递，通过e.currentTarget.id获取
6. 在navigateTo或redirectTo中传递参数

## 小程序的双向绑定

小程序之间的this.data的属性不能同步到视图，必须要调用this.setData方法来更新视图。

## 小程序的主要生命周期函数

1. onLoad，页面加载时触发，只执行一次，可获取当前页面路径中的参数
2. onShow，页面显示/切入前台时触发，一般用来发送数据
3. onReady，页面初次渲染时触发，只执行一次，页面已经可以和视图层交互
4. onHide，页面隐藏/切入后台时触发
5. onUnload，页面卸载时触发，如redictTo或navigateBack，一般用来销毁定时器、解绑事件监听等

## 原生小程序、wepy、mpvue

1. 原生小程序，使用原生的JS、WXML、WXSS，可以直接调用微信提供的API，缺乏组件化，但坑少，适合原生开发者
2. Wepy，Wepy 是一个基于 Vue.js 的小程序开发框架，旨在以更现代化的方式编写小程序。使用 Vue 的组件化开发模式，支持 ES6/7 语法和一些现代前端工具特性。开发者可以使用 Vue 的指令和生命周期函数等。但是，Wepy 的社区和生态相对较小。
3. mpvue 是一个由美团点评开源的框架，也是基于 Vue.js 的小程序开发解决方案。拥有较大的社区支持和生态，可以使用 Vue 的各种插件和库

## 提高小程序应用速度

1. 提高页面的加载速度，使用压缩图片、压缩代码、减少请求等方式
2. 用户行为预测，使用用户行为数据进行页面优化，比如用户停留时间、点击行为、浏览路径等
3. 减少默认data大小
4. 组件化，使用组件来提高代码复用性和可维护性

## 小程序的优劣

1. 容易上手、基础组件完善，开发文档完善，社区活跃，基本不考虑兼容问题
2. 良好的用户体验，不需要下载，速度快，也可以添加到桌面
3. 开发成本比APP低
4. 严格的审查流程，有利于提升产品质量

1. 限制较多，页面大小不能超多1M，不能打开超过5个层级的页面
2. 样式单一，部分组件样式成型，不支持自定义样式
3. 推广面窄，不适合大众推广

6. 真机测试，个别安卓和苹果表现迥异

我是用wx.getUserInfo获取用户信息，withCredentials为true，可以获取encryptedData,里面有unionId，可以用来确定用户唯一性。

##  小程序调用后台接口问题

1. 数据大小限制，超过范围会直接导致小程序崩溃；
2. 小程序不可以直接渲染文章内容这类html文本，需要借助插件

## 小程序下拉刷新

使用view代替scroll-view，并设置refresher属性，触发下拉刷新事件，在onPullDownRefresh中处理刷新逻辑。

## bindtap和catchtap的区别

bind事件绑定不会阻止冒泡事件向上冒泡，catch事件绑定可以阻止冒泡事件向上冒泡。

## 小程序路由

1. wx.navigateTo()：保留当前页面，跳转到应用内的某个页面，不能跳转到tabbar页面；
2. wx.redirectTo()：关闭当前页面，跳转到应用内的某个页面，不能跳转到tabbar页面；
3. wx.switchTab()：跳转到应用内的某个tabbar页面，并关闭其他所有非tabbar页面；
4. wx.navigateBack()：关闭当前页面，返回上一页面或多级页面。可通过getCurrentPages()获取当前的页面栈，决定返回几层。
5. wx.reLaunch()：关闭当前页面，重新打开应用，并跳转到应用内的某个页面。

## 小程序和Vue写法的区别

1. 遍历的时候，小程序是wx:for="list"，Vue是v-for="item in list"；
2. 调用data赋值的时候：
   1. 小程序是this.data.name，Vue是this.name；
   2. 赋值是this.setData({name: 'value'})，Vue是this.name = value。

## 小程序与原生APP

小程序：  
    优点：
   1. 基于微信平台开发，有微信buff
   2. 无需安装，只要打开微信就能用，不占手机内存，体验好
   3. 开发周期短
   4. 成本较少
   5. 小程序名称唯一，在搜索里面权重高
   6. 容易上手，学过前端基本没有太大问题
   7. 基本不考虑兼容性
   8. 发布、审核、上线流程简单
   9. 开发文档活跃、社区活跃
   10. 支持插件式开发，一些基本功能可以开发成插件供多个程序使用
  
原生APP：
   1. 原生的响应速度快
   2. 对于有无网络操作时，基本选用原生
   3. 需要调用系统硬件的功能
   4. 在无网络或者弱网情况下体验好
   5. 开发周期长，成本高，需要下载

## 小程序常见问题

1. rpx：使用rpx可以使小程序的UI适配不同屏幕大小
2. wx.navigateTo()无法打开页面，一个应用只能同时打开5个页面，避免多层级交互，使用redirectTo
3. tabBar不显示：
   1. tabBar的数量少于2项或超过5项
   2. tabBar写法错误
   3. tabBar没有写pagePath字段

## 微信实现支付功能

实现微信支付的三种方式：
1. 云调用，使用云函数免密调用微信支付接口，开发者无需关心证书、签名、微信支付服务器端文档，使用简单，代码较少，只需要调用相应的函数即可
2. 使用云开发工作流进行逻辑编排，通过连接器调用微信支付接口，相比云调用支持更加复杂、通用的业务场景
3. 云开发管理系统内置了「微信支付管理」模板，支持 Web 端登录使用，提供订单查询、退款等功能，开发者也可对模板进行自定义修改
