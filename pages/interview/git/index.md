# Git

## Git常用命令

1. git init 初始化一个仓库,将创建一个.git目录,后续操作记录都会在此文件夹中，相当于数据库
2. git remote add origin < url > 添加远程仓库地址,将本地仓库和远程仓库关联，origin为远程仓库名
3. git remote -v 查看关联的远程仓库列表，返回仓库名和url
4. git status 查看当前仓库状态，包括文件修改、新增、删除等
5. git add < file > 将文件添加到暂存区，等待提交
6. git commit -m "commit message" 将暂存区文件提交到本地仓库，并添加提交信息
7. git log --oneline 查看提交历史，返回提交id和提交信息
8. git diff 查看工作区的文件和暂存区的不同之处
9. git push origin <本地分支名> 将本地分支推送到远程仓库,第一次推送的时候远程仓库会在服务器上创建对应分支，后续可以直接使用git push
10. git pull 将远程仓库的最新内容合并到本地仓库
11. git merge <分支名> 将指定分支合并到当前分支
12. git merge --abort 放弃合并操作
13. git branch <分支名> 创建新分支
14. git checkout <分支名> 切换到指定分支
15. git checkout -b <分支名> 创建并切换到新分支
16. git branch 查看本地分支列表，-a参数显示所有分支，包括远程分支，-r参数显示远程分支
17. git branch -d <分支名> 删除本地分支,如果该分支没有合并过，报错，强制删除，使用-D参数
18. git clean -f 删除工作区未跟踪的文件,如果想删除目录，需要加-d参数
19. git reset 重置暂存区和上次commit保持一致，但不会重置工作区修改,需要使用git checkout <文件名>命令才能重置工作区。或者使用较危险的git reset --hard HEAD，将工作区和暂存区的重置到上一次版本，包括commit信息
20. git rm 文件名 删除文件，并将修改提交到本地仓库
21. git rm --cached 文件名 删除文件，但不提交到本地仓库，仅仅是从暂存区中删除
22. git stash 保存当前工作区的修改，等以后恢复，当开发时需要重新创建一个新分支去解决线上问题，但是此时又不想将当前的分支改动到对应分支上，可以使用该命令将修改(包括工作区和暂存区)保存到堆栈中
23. git stash pop 恢复上次保存的工作区的修改

## Git提交发生冲突

1. 发生冲突，在IDE里面对比本地文件和远程分支文件，把远程分支上文件的内容修改到本地文件，然后再提交，必要时与同事流交流消除冲突
2. 发生冲突，通过git stash将工作区的修改保留到栈区，通过git pull拉取远程仓库分支代码合并到本地分支；然后通过git stash pop把栈区的修改部分合并到工作区中去，再提交

## Git提交失误，如何撤销

1. git reset HEAD < file > 将暂存区的修改撤销，但不会改变工作区
2. git reset --soft HEAD^n 恢复当前分支的版本库至上一次提交状态，n为提交次数，如git reset --soft HEAD^2，恢复至上上次提交状态
3. git reset --mixed HEAD^n 恢复当前分支的版本库和索引区至上一次提交状态，工作区不变
4. git reset --hard HEAD^n 恢复当前分支的版本库和索引区和工作区至上一次提交状态

## Git和SVN的区别

1. Git是分布式版本控制系统，SVN是集中式版本控制系统
2. git相对于svn的优势是不需要网络即可版本控制
3. git把内容按照数据方式存储，svn按文件
4. git可以是公用的，可以分享，svn基本是公司内网才能访问
5. git不依赖于中央服务器，svn依赖于服务器
6. git没有一个全局版本号，svn有
分布式和集中式：
- 集中式版本控制系统：版本库存放在中央服务器，每个开发者都可以直接从中央服务器克隆版本库，提交代码，而不需要先从中央服务器下载代码。集中式版本控制系统的优点是简单易用，缺点是中央服务器宕机后，所有开发者都无法提交代码。
- 分布式版本控制系统：版本库存放在每个开发者的电脑上，每个开发者都可以提交代码，而不需要先从中央服务器下载代码。分布式版本控制系统的优点是每个开发者在没有网络的情况下也可以提交代码到本地仓库

## git fetch和git merge和git pull的区别

1. git pull相当于git fetch和git merge，将远程仓库的最新内容下载合并到本地仓库
2. git merge是将内容合并到当前分支
3. git fetch相当于是从远程获取到最新版本到本地，不会自动merge

## Git的rebase和merge的区别

1. git rebase和git merge都是用于从一个分支获取内容合并到当前分支
    Merge：
   1. 使用merge会自动创建一个commit，如果合并遇到冲突，只需要修改后重新commit即可
   2. 优点能记录真实的commit情况，包括每个分支
   3. 缺点是产生由于每次产生的merge会自动产生一个merge commit，导致历史记录变得复杂,且这些commit对于我们来说没什么意义
    Rebase：
   1. rebase会合并之前的commit历史
   2. 优点是可以得到更简洁的提交历史，去掉了merge commit
   3. 缺点是因合并如果有代码问题，就不容易定位
2. 当需要保留详细信息时，建议使用git merge，尤其是要合并到master
3. 当发现自己修改某个功能是提交比较频繁，可以尝试使用rebase
